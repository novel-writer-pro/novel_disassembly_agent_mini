# apps/web

独立前端目录。

当前前端正在向 **Next.js + React + Ant Design** 的产品结构迁移，目标是：
- 多页面 / 多组件可维护结构
- 面向作家的阅读型工作台
- 拆书结果卡片化渲染
- 原文回看与章节跳转

## 开发环境

建议 Node.js 版本：
- Node.js 20+

建议先设置 npm 源：

```bash
npm config set registry https://registry.npmmirror.com/
```

也可以只针对当前安装命令使用：

```bash
npm --registry=https://registry.npmmirror.com/ install
```

## 安装依赖

```bash
cd apps/web
npm install
```

## 开发启动

```bash
npm run dev
```

默认地址：

`http://127.0.0.1:4173`

## 生产构建

```bash
npm run build
npm run start
```

## 当前目标能力

- 导入小说入口
- 作品进度总览
- 多作品切换入口（当前为单工作台切换不同 run / branch）
- 左侧章节导航
- 右侧章节详情主视图
- 独立的小说问答页 `/qa`
- chapter bundle / QA context 结构化阅读
- 原始章节正文回看
- `第N章` 引用跳转
- 恢复动作
- 导出下载链接

## 说明

- 当前仓库里仍保留一部分旧静态原型思路，但目标是全面收口到 Next.js 前端
- 最终界面不应强调技术信息，而应以“章节、人物、事件、线索、原文、导出手册”为核心


## 当前产品化方向

当前页面已经不再按“开发原型 / 调试页”组织，而是按作家使用习惯组织：
- 小说空间：先从多本小说里选择当前生效作品
- 控制台：导入、进度、下一步建议
- 章节阅读：阅读提要、人物/线索、追问/推理、原文回看
- 导出与恢复：手册导出优先，恢复操作后置

## 多作品说明

当前 UI 已经支持在控制台里切换最近作品 / 分支，因此：
- 数据上不再局限于单本小说
- 交互上仍是“一个工作台一次聚焦一个 branch”
- 工作台头部会明确显示“当前作品”，控制台也会显示当前作品 / run / branch 摘要

当前新增了独立的 `/library` 小说空间页：
- 适合作为多本小说的管理入口
- 支持大量小说卡片浏览、搜索和切换
- 可以先选定当前作品，再进入阅读 / 问答 / 导出流程
- 已内置“多任务运行 / 恢复中心”，用于盯住正在跑和待恢复的小说
- 已支持自动状态刷新，运行中任务会更频繁刷新
- 现在会按 branch 记住各自的最后阅读章节，切回同一本小说时会尽量回到上次阅读位置
- 已内置“系统健康面板”，可直接查看 `.cache/novel-analyzer` 与历史 `.omx` 的运行时文件状态

也就是说，当前版本适合：
- 多本小说存在于同一数据库
- 在工作台里切换查看不同作品

但还没有做到：
- 多作品并排总览
- 多任务看板
- 多作品同时监控页

目前已经具备的基础形态更接近：
- 多作品管理空间
- 单工作台聚焦当前作品
- 每本书都有独立状态卡与快捷入口

## 问答状态说明

问答页当前会区分两种结果：
- 正常回答：上游模型可用，按正常流式回答展示
- 降级回答：上游模型临时不可用时，改为基于检索证据输出保守回答，并明确显示降级提示

## 当前推荐运行配置

前端默认建议配合以下后端运行：
- provider: `vip1129`
- base_url: `https://api.vip1129.cc/v1`
- model: `gpt-5.4-mini`

## 恢复机制说明

章节失败时：
- 系统先自动重试
- 当前自动重试上限为 **5 次**
- 超过 5 次仍失败，才需要人工进入“导出与恢复”页处理


## 新增：检索与问答

当前工作台已提供独立问答页 `/qa`，并保留检索与问答能力：
- 人物 / 事件检索
- 基于整本小说的问答
- 聊天式问答输入与消息流
- 流式回答展示（stream 优先，必要时自动回退）
- 回答中的引用章节跳转
- 证据摘要、推理路径、图谱信号展示
- 顶部概览卡 + 侧边提问记录，方便长会话中持续追问
- 检索结果一键转问答，支持围绕某一章继续深挖

当前推荐体验：
- 在 `/qa` 页直接像普通 chat 一样提问
- 如果想先定位人物或事件，再切换到“快速检索”页签
- 如果想回看依据，可点击回答中的章节引用跳转到 `/reader`

## 构建缓存异常排查

如果 `npm run build` 报类似：
- `Cannot find module for page: /ops`

但 `src/pages/ops.tsx` 实际存在，通常是 `.next` 构建缓存脏了。可直接执行：

```bash
cd apps/web
rm -rf .next
npm run build
```

当前已验证这能恢复 `/ops` 页面进入构建产物。

- 问答 / 检索台会优先显示在阅读页上方，避免被章节详情淹没。
- 现已调整为独立顶级问答页，避免和章节阅读主视图互相挤压。

- 导出文件不再依赖 `/tmp` 临时目录，当前改为项目内持久导出目录，前端刷新后下载链接更稳定。

- 如果章节因为 provider 当日额度耗尽而失败，控制台首页会显示醒目的额度提示，并引导进入“导出与恢复”页。

- 如果阅读页报原始章节正文文件不存在，当前版本已改为将上传小说持久化到 `.cache/novel-analyzer/uploads/`，不再依赖 `/tmp`。

- 工作台导航现分为：开始整理 / 章节阅读 / 小说问答 / 导出与恢复。

- 根路由 `/` 现在直接进入控制台，不再用 `router.replace` 跳 `/control`。
