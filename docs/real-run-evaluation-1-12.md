## 4. 已观察到的短板

### 4.1 writer-learning 仍偏弱
尽管我们已经增强了 fallback，但当前真实章节里的 `writer_learning_notes` 仍然偏少、偏弱。

### 4.2 summary 仍偏长
部分章节 summary 更像“剧情概述”，还不够卡片化。

### 4.3 当前模型 JSON 稳定性一般
在长跑过程中已经真实出现过：
- 章节返回损坏 JSON
- 需要 `retry-chapter`

说明当前模型：
- 内容质量不差
- 但结构化输出稳定性一般

### 4.4 当前模型吞吐偏慢
在真实章节上，单章耗时明显偏长。
这会影响无人值守的长程跑批体验。

---

## 5. 当前模型结论

### 结论一
当前模型：
**适合做质量验证 / 人工盯跑**

### 结论二
当前模型：
**不适合做长程无人值守生产跑批**

原因：
- JSON 稳定性不够高
- 单章耗时偏长
- 长跑中需要人工关注失败与重试

---

## 6. 当前最推荐的使用方式

### 推荐方式
- 每次推进 3~5 章
- 每个窗口做一次人工复盘
- 关键失败章立即重试
- 以 `branch report + chapter markdown + qa context` 为主审阅

### 不推荐方式
- 一次性无人值守跑 100 章以上
- 不做中间复盘直接看最终结果
