# Feature Checkout / 功能结账入口

这一组文档用于回答每一次推进时最关键的 6 个问题：

1. 当前到底做了什么
2. 还缺什么
3. 预期效果是什么
4. 解决了什么问题
5. 当前测试 / 评估是否达到预期
6. 还需要哪些闭环与优化

维护规则：
- 每次跨能力线推进（retrieval / risk / imitation / eval / docs IA）都应该补一份 checkout。
- checkout 应该优先记录“可验证事实”，而不是口号。
- checkout 不是 changelog 的替代品；它更像当前阶段的经营看板 + 技术收口页。
